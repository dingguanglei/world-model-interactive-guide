04 / REAL-WORLD RL

强化学习，
只写真实可执行的方法。

本章不做 RL 教科书，只记录机器人真实数据如何进入 value/policy 更新，以及探索、回滚和安全边界如何落到控制回路。

⏰ 最后更新时间: 2026-08-13 | 查看更新日志；本页内容将每日更新「真实机器人强化学习算法、数据接口与安全约束」。

1) 算法 → 数据 → 实机约束

方法具体更新机制真实机器人用法主要风险
CQL
UC Berkeley / Google Research		对数据集外动作施加保守 Q 惩罚，避免 critic 对 OOD action 过估计用遥操作/UMI/历史 rollout 做 offline pretrain，再小流量在线微调数据覆盖不足时过度保守；奖励和 Q 标定仍需实机验证
IQL
UC Berkeley		用 value expectile 拟合数据内高价值动作，再 advantage-weighted BC 提取 policy适合先从固定示范集学，再接真实交互 fine-tune行为数据质量决定上限；未覆盖动作不能靠算法凭空补齐
Residual RL
UC Berkeley / Google Research		固定 controller 输出 base action，RL 只学习 residual action：a = a_base + a_res把接触、摩擦、个体差异交给 residual；基础控制器保留稳定性残差幅度、频率和安全投影必须限幅，否则会破坏 base controller
Incremental Residual RL
Kyushu University		增量更新 residual，不依赖 replay buffer 或大 batch 更新适合边缘设备和环境变化明显的在线适应；论文包含真实环境实验更新信号必须低噪，且需要策略冻结/回滚机制
Safe RL / CBF将动作送入 control barrier function、QP projection 或 safety shield 后再执行把碰撞、关节限位、速度/力矩约束放进每个控制周期安全层可能改变探索分布；需要单独测可达性和性能损失

3) 仿真训练：算法按数据机制选，不按热度选

仿真负责并行采样、失败放大和回归；策略部署前仍须在真实传感器、延迟与安全层上复核。以下是当前连续控制/操控环境里可落地的主流选择；每一行都给出奖励设计会受影响的地方。

算法 / 来源机构更新目标（原理）具身仿真中的用法奖励设计与使用边界
PPO
OpenAI · 2017		用新 rollout 的 advantage 更新策略；将概率比 πnew/πold 裁剪，限制每轮策略漂移。
on-policy：旧轨迹不能反复复用。		Isaac Lab/Isaac Gym 的大规模并行采样很适合腿足、人形、接触丰富的 locomotion；用 GAE + 多环境 rollout 换取稳定 wall-clock。先用命令跟踪、姿态/接触稳定、动作变化率与力矩项，逐步加入地形与扰动 curriculum。不要把 success 只藏在 dense reward 里；单独报成功率。
SAC
UC Berkeley / Google Brain · 2018		replay buffer 上训练双 Q 与随机 actor；最大熵项鼓励探索，温度自动调节探索强度。
off-policy：可复用仿真与真实旧数据。		适合低维 state 的抓取、灵巧手和单环境成本较高的操控；先以示范/成功 replay 填充 buffer，再让策略从受限初始状态探索。以终止成功为主信号，reach → grasp → lift → place 的进度项要按事件门控。replay 中需保留失败、掉落和接管样本，避免 critic 只见“干净成功”。
TD3
McGill University · 2018		双 critic 取较小 target、延迟 actor 更新、target action 加平滑噪声，压制连续动作的 Q 过估计。
deterministic off-policy。		低维状态、连续动作的到位/推拉/参数化技能可作为 SAC 的清晰对照；视觉任务必须额外审计 encoder 与 replay 的分布漂移。稀疏成功不足时，用距离/姿态 potential 降低探索方差；不要只堆大负碰撞分数，否则策略会学到静止或远离任务。
DreamerV3
Google DeepMind · 2023		学习 latent world model，在 imagined futures 中更新 actor/value，而非每次都向 simulator 取样。
model-based actor-critic。		适合视觉观测、长时序或 sparse-success 的仿真任务：模型把图像序列压入 latent，再从 imagined rollout 训练行为。reward predictor 的误差会被 imagination 放大。将真实回放的 success、接触和安全事件作为单独 held-out 检查；不能以 imagined return 宣称可部署。
TD-MPC2
UC San Diego · 2023		学习隐式、无 decoder 的 latent dynamics，并在 latent 中做局部 trajectory optimization；ManiSkill 将其列为在线 model-based 基线。连续控制中需要短视界规划、动作约束或多任务 state 输入时可用；每个控制周期重规划并用 value/policy prior 缩小搜索。规划 objective 必须把碰撞、接触力和动作变化率显式计入；模型不确定时降低规划视界或切回保守控制器，不能仅提高 reward 权重。
AMP
UC Berkeley · 2021		从无标注 motion clip 训练 discriminator，将“像参考运动”的分数作为 learned style reward；通常附加在 PPO 的任务奖励上。人形行走、转向、跌倒恢复和全身动作：用 motion prior 缩小可探索动作空间，再以任务 reward 学命令跟踪或搬运。style 分不能替代任务 success，也不能替代碰撞/力矩限制。须检查策略是否为拿高 style 分而原地踏步、拒绝接触或绕开目标。

实现参照：ManiSkill 官方 RL baselines 公开维护 PPO、SAC 与 TD-MPC2；算法原论文链接见表中标题。

4) 奖励设计：先定义成功，再做受约束的塑形

通用操控模板（示意）：r = wS·1[success] + wR·exp(-||xobj-xgoal||²/σx²) + wG·1[grasp] + wL·1[grasp]·clip(h-h0) − wΔa·||at-at-1||² − wτ·||τ||² − wC·bad_contact。其中 1[success] 是验收指标；其余项只负责让探索更快，不能掩盖失败。

任务建议项（具体函数）门控 / 终止条件必须看的 reward-hacking 迹象
抓取—搬运—放置rreach=exp(-||pee-pobj||²/σ²)；rgrasp=1[两指接触且物体相对速度低]；rlift=1[grasp]·clip(h-h0)；rplace=1[grasp]·exp(-pose_error²/σ²)。掉落、桌面外、超力或自碰撞立即终止/交给 shield；放置项只在已 grasp 后启用，成功要检查稳定停留而非瞬间过线。末端在物体旁抖动刷 reach；把物体推近目标但未抓住；快速穿模/撞击取得短暂 pose 分；到达后立即掉落。
腿足 / 人形命令跟踪rv=exp(-||vxy-vcmd||²/σv²)；rω=exp(-(ωz-ωcmd)²/σω²)；upright/foot-air-time；rΔa=-||at-at-1||²；rτ=-||τ||²。躯干高度/倾角、关节限位、非法接触、接触力超阈值作为 termination 或 safety constraint；命令范围与地形难度用 curriculum 调，不靠突然改奖励。原地高频摆腿刷 foot-air-time；趴低以减小能耗；用脚背/膝盖滑行仍拿速度分；动作平滑项过大导致拒绝执行命令。
插拔 / 接触装配关键点 rkey=exp(-Σ||ki-k*i||²/σk²)；轴向深度、姿态误差、低横向力；动作变化率惩罚。接触力、横向偏差、卡死时间和超行程须独立终止；只在对齐阈值内开放深度奖励，避免“侧撞硬塞”。利用接触模型震荡累积奖励；在孔口附近徘徊；以超过真实可承受力的动作换取一次成功。

可迁移的塑形规则。 对距离或子目标定义势函数 Φ(s) 时，用 F(s,s′)=γΦ(s′)−Φ(s) 加到原 reward；Ng、Harada、Russell（UC Berkeley，1999）给出这种 potential-based shaping 保留最优策略的条件。每个系数需按控制周期复核：Isaac Lab RewardManager 会将每个 reward term 乘以环境 dt。官方库也直接提供 速度跟踪、action-rate、非法接触与接触力 项。

上线前审计顺序。 逐项记录未加权值、加权贡献和终止原因；关闭每个 shaping 项重跑；最后在真实观测/延迟/动作限幅下重算 success、碰撞、接管和超力。奖励可在仿真里读取特权 state，但部署验收必须有可测的真实代理量，且 policy observation 不得偷用该 state。

5) 只接受这类实机证据

  • 报告真实机器人交互步数或部署时长，而非只给仿真 episode。
  • 说明 reward 来源：任务成功、进度、接触/力、人工偏好还是规则函数。
  • 说明策略更新频率、数据是否进入 replay buffer、旧策略如何回滚。
  • 将 real-robot success、recovery、intervention、safety violation 分开统计。
🧠 AI 评论

判断：真实 RL 的工程核心是“可控地改变一点点”，不是让机器人无约束地探索。优先级应是 offline 初始化 → residual 微调 → safety projection → 小流量实机验证 → 失败回滚。
